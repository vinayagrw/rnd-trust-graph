What the industry does (July 2026)

Five approach families — layered, not chosen

Click a card. The recommendation stacks four of them and excludes one from the grounded path.

Family 1 · delivery channel — adopted
Tool-call → registered renderers
LLM emits a typed tool call; a pre-registered React component renders it. The dominant production pattern — and exactly what render_evidence already is.
Where it fits ▾
Implementations CopilotKit renderToolCalls/useRenderTool · Vercel AI SDK client tools (RSC streamUI paused) · assistant-ui
Wins / breaks Strongest trust story; constrained to your component library. Breaks on novel layouts — those need code.
Role here The transport: render_dashboard rides the same verified AG-UI TOOL_CALL_* channel as today's five tool calls.
Family 2 · spec language — adapted
Declarative UI-spec (A2UI-shaped)
The LLM writes a JSON component tree, validated against a closed catalog. Where the industry converged in 2026 — A2UI v1.0-RC, Open-JSON-UI, json-render.
Where it fits ▾
Adopt vs adapt A2UI GA lands Q4 2026 and already broke once (0.8→0.9). Decision: custom Zod spec now, deliberately A2UI-shaped (flat list, ids, data-by-reference), one-seam adapter later.
Key alignment A2UI natively separates literals from JSON-Pointer data references — the same "no inline values" rule our grounding demands.
Role here The composer's output language: shared/dashboardSpec.ts.
Family 4 · deterministic floor — adopted
Template slot-filling
Code derives a dashboard from cited node kinds + intent — no LLM, zero latency. The app's F5 playbooks and GroundedDiagrams auto-select are already this family.
Where it fits ▾
Wins Deterministic, auditable, instant first paint. NL2Dashboard (Jan 2026) argues this is the controllable core of dashboard generation.
Role here Always present: the instant first paint and the fallback when the composer fails validation twice. The feature can never degrade below today's behavior.
Family 5 · planner — thin, phase 2
Agentic composer
Planner → per-widget binder → critic pipelines (Databricks Genie-class). Powerful, slow, hard to eval.
Where it fits ▾
Verdict Multi-call pipelines are unaffordable on a 10–25s/call local provider. One bounded composer call (with a fast-tier route) captures most of the value.
Role here A thin planning step only — never a top-level autonomous controller.
Family 3 · excluded from the grounded path
LLM-written code in a sandbox
Artifacts-style generated HTML/JS in a sandboxed iframe (MCP Apps is the tamer pre-authored cousin). Unlimited expressiveness — and the one family that cannot prove it renders only graph-derived facts.
Why it's out ▾
Why excluded Model output becomes executable (OWASP LLM01 class); can't share the app's React context or design tokens; slowest to first paint; grounding unprovable. Acceptable someday as an explicitly-labeled exploratory escape hatch — never the trust surface.

Why this wins

The differentiator is trust, not chart generation

Databricks Genie and Snowflake Intelligence generate charts from natural language today. None of them show per-widget query provenance, faithfulness scoring, and in-thread human review as first-class UI. This design makes every generated dashboard more auditable than the static panel it replaces — the exact Cypher, timestamp, record count, model version, and review status ride with every widget. That is the on-screen reproducibility a GxP-adjacent reviewer expects, and the claim no agentic-BI vendor currently makes.
